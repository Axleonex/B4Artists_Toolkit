# Plan 02-05: named layouts and persistence

**Goal:** Let artists save and switch their own toolbar arrangements.
**Architecture:** Validated layout library stored in the preference record,
native CRUD dialogs, existing settings import/export. **Tech stack:** JSON/RNA/bpy.
Execute sequentially; all behavior uses the model from 02-02.

## Task 1: implement pure library operations

**Modify:** ui/timeline_config.py, tests/test_timeline_config.py.

**Do:** Functions for Save As, Update Saved, Load, Rename, Delete, Reset
Recommended and modified-state comparison. Deep-copy active layout into saved
records. Name rules: trimmed nonempty Unicode <=64 characters, unique after
casefold; error on duplicate, never silent overwrite. Stable UUID identity
survives rename. Recommended is built-in/read-only. Delete removes library
entry; if active entry was deleted, keep active working layout as Custom rather
than replacing it. Reset loads recommended presentation but preserves library.
Loading a layout with unavailable modules preserves its choices and shows disabled
tools rather than dropping them. Neither library nor dirty flag stores preview values.

**Verify:** Pure tests for Unicode/duplicate/empty/long names, rename identity,
deep-copy independence, delete active/inactive, restore keeps layouts, modified
marker, missing module/action and invalid import preservation.

**Done means:** Named layouts behave predictably and cannot lose user work silently.

## Task 2: expose native layout controls

**Modify:** ui/timeline_settings.py, prefs.py.

**Do:** Layout picker shows Recommended, saved names and Custom/modified status.
Add Save As, Update Saved Layout, Load, Rename, Delete, Restore Recommended.
Save As asks for name; Update targets an existing custom ID explicitly; Rename
cannot collide; Delete uses native confirmation. Cancel leaves everything intact.
Layout switch applies only presentation/launch defaults, not animation or scene
scope. Warn before replacing unsaved working edits with a loaded layout; offer
Save As or explicit discard. Main row stays compact; library UI lives in Settings.
If auto-save preferences is off, show existing Save Preferences action clearly.

**Verify:** Native dialog walkthrough saves Blocking and Polish, modifies active,
renames, deletes one, restores recommended, and loads the remaining layout.
Animation/clipboard/scene reference/selection hashes stay equal. UI labels match
actual library state. No library operation proceeds during active slider drag.

**Done means:** Artists can name and recover their own arrangements without files.

## Task 3: persist and transfer validated records

**Modify:** operators/settings_ops.py, prefs.py, tests/check_timeline_toolbar_tools.py.

**Do:** Include versioned record in existing settings JSON transfer. Validate
complete layout data before assignment; malformed JSON/future schema reports
error without partial state loss. Support old Boolean-only export migration.
Use package-aware preference ID for legacy/extension install names. Save only
inside asserted isolated CONFIG during tests. Relaunch normally (no
--factory-startup when checking preferences), confirm automatic addon enable,
active layout and all saved records. Save/reopen a generated blend separately
to prove scene-specific options remain scene-specific.

**Verify:** Byte-normalized model equality before save and after new process;
named library, active identity, order/modes/ranges/presets equal. Export/import
roundtrip with bad import negative case. User profile remains untouched.

**Done means:** Custom named layouts survive real restarts and settings transfer.

# Plan 02-04: render controls and native settings windows

**Goal:** A compact, understandable A-based row with configurable popout sliders.
**Architecture:** Extend existing theme-derived pixel band and native input;
native RNA dialogs for configuration. **Tech stack:** gpu, blf, bpy dialogs/RNA.
Execute sequentially after adapter verification.

## Task 1: compute bounded geometry

**Modify:** ui/timeline_overlay.py, ui/timeline_config.py,
tests/test_timeline_overlay_layout.py.

**Do:** Replace label-only specs with structured control records: action/kind,
label, mode, family, rect, track rect, value rect, preset/reset/settings hits.
Use stable ID rather than label for hit testing. Reorder presentation to
Tween/Timing/Curves/Keys/Pose/Bake/Motion. Reserve right utilities first. Keep
family labels/menu access; show configured entries in saved within-family order.
Minimize labels/widths before demoting inline presentation to Popout, then put
overflow in More. All tools remain reachable via More/Search. Narrow appearance
does not write modes/order. Clamp temporary track inside originating canvas;
its rectangle must avoid clipping or cover the controls required to cancel.
Freeze control/track geometry during a drag, or cancel before a resize rebuild.

**Verify [PowerShell]:** `python -m unittest discover -s tests -p test_timeline_overlay_layout.py -v`.
Update old expectations that assume Search/Settings on the left. Test 250,
480, 800, 1164, 1920 widths and 1/1.5/2 scales, top/bottom placement, all tools
shown, empty layout, custom order and extreme track widths. Assert bounds,
no overlap, utility reachability, stable IDs and untouched serialized config.

**Done means:** Width changes never force panning, overlap or preference resets.

## Task 2: draw theme-aware icons, sliders and feedback

**Modify:** ui/timeline_overlay.py.

**Do:** Draw functional family/action glyphs using small GPU primitives and
existing host conventions; preserve labels by default. Draw tracks/thumbs,
numeric readout, pin indicator and reset/presets. Show disabled controls with
clear explanation; hover actual scope and Breakdown anchor hint. Render popout
feedback from transient session data only. Keep the native ruler and playhead
clear where possible, as existing top-header behavior requires. No tutorial
cards, mockup labels, implementation text or default onboarding window.

**Verify:** Still screenshots at rest/drag/disabled, active host theme and
actual UI scale 1/1.5. Measure contrast and target geometry. Source/rendering
inspection confirms idle redraw never writes scene properties. Readout units
agree with adapter values. Default shows exactly two persistent tracks.

**Done means:** Users can see what they will adjust before starting a gesture.

## Task 3: connect native row input to verified transactions

**Modify:** ui/timeline_overlay.py, ui/timeline_strip.py,
tests/check_timeline_overlay.py.

**Do:** Extend band hit tests to slider controls. Scalar Button retains existing
dispatch; Inline/Popout starts the new slider operator with origin/geometry.
Idle right-click opens tool settings; during modal it cancels. Preset/reset
uses one verified transaction with explicit launch value. Outside the band
returns PASS_THROUGH; hovering updates only this window's row. Input disabled
state and all guard checks match existing _unavailable behavior. Modal session
owns input only until commit/cancel. Preserve View Show/Hide control, handler
cleanup and existing one-time collapsed-Timeline behavior; do not add a new
repair timer or change native header lengths.

**Verify:** Native events perform Breakdown/Smooth inline and Scale popout;
readouts follow actual effects. Press/hold/move/release, zero-motion click,
right-click cancel, Enter and Shift all measured. Scrub, middle pan, wheel zoom,
playback and neighboring-editor click work outside band. Toolbar remains stable
while native borders are dragged; screenshots are sampled evidence, not a
universal flicker claim.

**Done means:** Direct adjustment needs no submenu and does not hijack native input.

## Task 4: build Toolbar Settings and per-tool Settings dialogs

**Create:** ui/timeline_settings.py. **Modify:** ui/timeline_strip.py and prefs.py.

**Do:** Native `invoke_props_dialog` with a family selector and list of every
tool's display mode, label/icon option, move-up/down and applicable width.
Stage edits in operator/temporary RNA data; Accept validates/applies one
presentation update; Cancel discards it. Toolbar Settings and preference panel
share one configuration source. Every list entry has Open Tool Settings.
Scalar dialog includes validated units/range/default/sensitivity/precision,
supported snap/presets and verified overshoot; identify existing masks/anchors
as scene settings and reuse their current options panel. No cloned target or
reference state. Immediate tools open existing relevant options and do not show
unsupported slider fields. Runtime launch receives overrides transiently;
never let an active layout silently rewrite a different scene's saved scope.

**Verify:** Native dialogs edit all four modes on a scalar and only two on Copy.
Cancel leaves configuration and animation hashes unchanged. Invalid range or
unsupported mode has an actionable error. Tool options correctly affect the
next gesture; existing settings panel reflects actual scene-specific choices.
Right-click and explicit settings action open the same window.

**Done means:** Artists can choose all displayed features and configure each tool.

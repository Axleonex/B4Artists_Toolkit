# Published-model screen - 2026-09-09

This bounded source review tests whether an existing pretrained system offers a practical alternative to further nearby fits on the current 17.1-minute corpus. No external code, weights or datasets were downloaded, installed or incorporated. No candidate was benchmarked or selected. These are distribution-screening observations, not a comprehensive legal determination or an exhaustive model search.

| Candidate | Verified publisher information | Decision for this project |
|---|---|---|
| AI4Animation (Unity) | The repository limits the project to research/education and states that commercial use or redistribution is not freely available; mocap is CC BY-NC 4.0. | Do not adopt its software/data as the freely distributable core on the basis of repository availability. [Publisher notice](https://github.com/sebastianstarke/AI4Animation#copyright-information). |
| AI4AnimationPy | The publisher describes NumPy/PyTorch, headless/manual operation and locomotion demos, but licenses the framework CC BY-NC 4.0. Its feature list marks rigid-body/collision simulation as future work. | Useful architectural reference; not a verified unrestricted replacement for the standalone core, and its scope does not itself establish the requested full physics workflow. [Publisher README](https://github.com/facebookresearch/ai4animationpy). |
| ProtoRes author repository | The inspected boreshkinai/protores-boris license permits non-commercial academic research. | Do not copy this implementation into the distributed add-on under an assumption of permissive licensing. This observation applies to the inspected repository, not every possible implementation of the published method. [License](https://github.com/boreshkinai/protores-boris/blob/master/LICENSE.md). |
| CondMDI | The implementation is MIT licensed and provides pretrained models; its README says all supplied models were trained on HumanML3D. | Relevant motion-inbetweening comparison candidate, but the inspected code license does not establish the complete weight/data/body-model distribution chain. No weight adoption is authorized by this screen. [Code license](https://github.com/setarehc/diffusion-motion-inbetweening/blob/main/LICENSE), [model provenance and setup](https://github.com/setarehc/diffusion-motion-inbetweening). |

HumanML3D reports 28.59 hours of motion and explains that its motion data must be reproduced from AMASS because it cannot directly distribute those source motions. Its published setup also uses body-model assets. This is evidence that matching a published model involves a materially different data/dependency pipeline; it does not prove that more data alone will solve our failures or determine the legal status of every trained weight. [HumanML3D publisher](https://github.com/EricGuo5513/HumanML3D).

The initial result is that none of these inspected routes is yet a verified, drop-in, freely distributable solution. Do not turn that limited result into a claim that no suitable model exists. A next candidate needs a specific checkpoint, verified code/weight/data terms, compatible skeleton and conditioning, bounded local resource use, and comparison on the same complete animator tasks before adoption. No additional fitting follows automatically from this review. The six project confirmation clips remain unopened, and all original quality requirements remain unchanged.

# Full-hierarchy model comparison v1

The prior learned-motion work is not the architecture to keep iterating. It used world-space selectors, mixtures and Transformers to choose or adjust procedural curves. Two independently trained mixture Transformer seeds failed the unchanged development gates. The resulting hard stop rules out more nearby selector, Transformer and loss-weight variants.

This comparison changes three things together: the predicted state, the condition contract and the model family. It uses the complete 23-joint ancestor-local hierarchy, fixed proportions, root translation and continuous 6D rotations. The 17 semantic controls remain the animator-facing constraint surface. Exact authored values are projected back after each learned proposal, then the existing deterministic FK, limits, contact/balance/collision refinement and original-rig validation remain in charge of correctness.

The fixed candidates are a bidirectional masked residual temporal-convolution network and a constraint-conditioned temporal diffusion U-Net. The convolutional model establishes whether a fast sequence generator can improve the procedural baseline. Its 253-frame receptive field covers the maximum 97-frame input without unnecessary down/up-sampling. The diffusion model tests whether the task needs a multi-modal distribution for partial poses and timing. Neither has been preselected as the winner.

Both receive the same 483-feature conditioning schema, use 8–96 frame sparse-key gaps, and train only on the frozen 68 subjects. The 17-subject future-development cohort selects a candidate only if every retained gate and every declared task/gap cohort passes. Confirmation remains sealed. The retained procedural baseline is measured under the same conditions and remains labelled procedural.

Weak foot-contact proposals can enter training only with 50% condition dropout and 0.35-or-lower confidence. Development cannot derive a contact condition from hidden target motion; its primary condition is unknown contact. Scene geometry, hand contact, moving supports, intent and naturalness remain unknown until separately measured or reviewed.

Deployment is separate from training: Bforartists must use CPU ONNX Runtime or an equivalent local inference implementation. It must not require PyTorch, an online account, Cascadeur, paid APIs, Ghost Tool or Anim Assist. The warm and cold inference targets are 25 ms and 250 ms, measured on the Bforartists host for each supported gap rather than inferred from desktop training timing.

The environment audit found ONNX Runtime 1.26.0 in the system Python. The existing unmodified ComfyUI embedded environment qualified PyTorch 2.10.0 with CUDA 13.0 on the RTX 5070 for training. The failed dedicated G: environment was removed. PyTorch remains a training-only dependency and is not part of the standalone Bforartists deployment design.

The fixed temporal-convolution candidate is implemented with 711,053 parameters. Its 766 inputs contain the 141-feature procedural state, 483 constraint/provenance features and a 142-feature boundary-motion block. The boundary block reads only previous-to-start and end-to-next motion and is invariant to hidden inbetween edits. The model contract proves that zero-initialized weights reproduce the procedural baseline exactly, authored controls remain exact, gradients are finite, and a 97-frame forward pass takes 3.9891650001663947 ms in the CUDA training environment. That timing is evidence of feasibility only; deployment latency still has to be measured inside Bforartists. The differentiable hierarchy contract also preserves synthetic bone lengths to within 1.4901161193847656e-08 and propagates root, pose, velocity, acceleration and contact losses through all 23 joints.

The plan and its fail-closed contract are [in the training directory](../../training/b4artists_ml/full_hierarchy_model_comparison_plan_v1.json) and `check_full_hierarchy_model_comparison_plan_v1.py`. The original product requirements, human assessment requirement and direct Cascadeur comparison requirement remain open.
